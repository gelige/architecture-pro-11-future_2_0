# Расширенный технический радар

## Целевой ландшафт

Доменные сервисы Go/Java/Python и их БД → outbox → Kafka и каталог схем → потоковые обработчики →
доменные витрины ClickHouse → семантический API → портал самообслуживания / Power BI.

S3 хранит разрешённую историю для пересчётов; каталог данных содержит владельцев, контракты, качество и lineage.
Общая платформа предоставляет инфраструктуру, доступ, наблюдаемость и шаблоны; домены владеют данными и SLO.

Базовое облако Yandex Cloud, отдельные проекты/сети/квоты доменов и среды dev/stage/prod.
Критичные компоненты резервируются по зонам; региональные контуры выбираются с учётом локальных требований.

Медкарты, истории болезни и результаты исследований остаются в клиническом контуре: они не попадают
в аналитические события, S3, каталог содержимого и BI. В аналитику поступают только разрешённые проекции.

## Технологии и платформы

| Технология                           | Статус | Назначение и основание / условие следующего решения                                       |
|--------------------------------------|--------|-------------------------------------------------------------------------------------------|
| Yandex Cloud: Compute, VPC, IAM, KMS | Adopt  | База из Task1; изоляция доменов, шифрование, квоты и отказоустойчивость                   |
| Terraform, GitHub Actions            | Adopt  | Воспроизводимые среды и CI/CD из Task1–2, инфраструктурные проверки                       |
| Go / Java / Python                   | Adopt  | Сохранение компетенций: финтех и доменные сервисы / ИИ в отдельном контуре                |
| S3-совместимое Object Storage        | Adopt  | История разрешённых событий, архив и резервные копии с политиками хранения                |
| Power BI                             | Adopt  | Сохранить пользовательские отчёты, переключать на утверждённые семантические модели       |
| OpenTelemetry, Prometheus, Grafana   | Adopt  | Сквозная диагностика, consumer lag, DLQ, качество и стоимость продуктов                   |
| PostgreSQL                           | Trial  | Операционные БД новых сервисов; Adopt после проверки транзакций, outbox и восстановления  |
| Apache Kafka (managed)               | Trial  | Общая событийная платформа; Adopt после пилота, проверки replay, отказа зоны и бюджета    |
| Apicurio Registry                    | Trial  | Версии схем и проверка совместимости в CI; Adopt после блокировки несовместимых изменений |
| ClickHouse (managed)                 | Trial  | Доменные аналитические проекции; Adopt после тестирования на пилотной нагрузке            |
| DataHub                              | Trial  | Каталог продуктов, владельцев, lineage; Adopt после регистрации всех пилотных продуктов   |
| OIDC / Keycloak                      | Trial  | Единый вход в портал; Adopt после проверки RBAC/ABAC и аудита доступа                     |
| Apache Flink                         | Assess | Сложные окна и event-time; Trial только если простые Go/Java-потребители не обеспечат SLO |
| Kubernetes                           | Assess | Проверить необходимость оркестрации; в базовом бюджете VM и managed-сервисы               |
| SQL Server 2008, PowerBuilder        | Hold   | Новую логику не добавлять; переносить в сервисы и веб-интерфейс по доменам                |
| Apache Camel как общая ESB           | Hold   | Только временные адаптеры совместимости; вывести после миграции потребителей              |

## Архитектурные и организационные паттерны

| Паттерн                                | Статус | Для чего нужен                                                                            |
|----------------------------------------|--------|-------------------------------------------------------------------------------------------|
| Данные как продукт (Data as a Product) | Adopt  | У каждого набора данных есть владелец, описание и требования к качеству                   |
| Outbox, идемпотентность, DLQ           | Adopt  | Не терять события, безопасно обрабатывать повторы и отдельно разбирать ошибки             |
| Контракты данных                       | Adopt  | Согласовать формат данных и сохранять совместимость при изменениях                        |
| Федеративное управление данными        | Adopt  | Общие правила доступа и качества при ответственности доменов за свои данные               |
| Strangler Fig / защитные адаптеры      | Adopt  | Постепенно заменять DWH и Camel, изолируя новые сервисы от старых моделей                 |
| FinOps / учёт затрат по доменам        | Adopt  | Контролировать расходы платформы и каждого домена                                         |
| Data Mesh                              | Trial  | Домены управляют своими данными на общей платформе; пилот в пациентском потоке и расчётах |
| Событийная архитектура (EDA)           | Trial  | Домены обмениваются событиями вместо общей логики в DWH                                   |
| CQRS / потоковые витрины               | Trial  | Обновлять отчёты по событиям, не нагружая операционные БД                                 |
| Self-service BI                        | Trial  | Пользователи самостоятельно строят отчёты в пределах своих прав                           |
| Saga / компенсации                     | Trial  | Согласовывать шаги междоменных процессов и компенсировать их при сбоях                    |
| Общий DWH как центр бизнес-логики      | Hold   | Не развивать: мешает независимым изменениям и подключению направлений                     |
